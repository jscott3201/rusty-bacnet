Discovery is a network operation, not a passive scan of a file. Start with the smallest authorized scope that answers your question.

## Use a known address first

```sh
bacnet discover --target 192.168.1.100 --wait 3
```

The directed option requires an address rather than a device instance or a `DNET:instance` expression. A known direct read can still be worth testing when a controller does not answer discovery.

## Discover a local network

```sh
bacnet discover 1000-2000 --wait 3
```

The range limits the requested device instances; it does not make a broadcast into a unicast operation. Confirm the interface, broadcast destination, and network owner approval before expanding the scope.

## Work across subnet boundaries

The CLI can run as a foreign device of an authorized BACnet/IP BBMD. It registers before the command, renews the registration (every `--renewal` seconds, half the `--ttl` by default) and sends the Who-Is through the BBMD:

```sh
bacnet --foreign-bbmd 192.168.1.1 --ttl 300 discover --wait 3
```

`discover --bbmd` only registers once before discovering; its Who-Is still goes out as a local broadcast.

Use a BBMD designated by the site owner. Registration changes BBMD foreign-device state. It is not a generic VPN or NAT workaround, and it is not part of BACnet/SC or IPv6 setup.

`discover --dnet 2` requests discovery for a remote BACnet network. It does **not** establish that every other command supports `2:1234` as a routed target. The one-shot `read`, `readm`, `write`, `writem` and `subscribe` commands take it, and the other one-shot commands refuse it. A direct router IP is not automatically equivalent to the downstream device's BACnet address.

## Keep discovery and device-instance lookup in one session

Plain `bacnet` on a terminal opens the terminal UI, whose device list keeps what it discovers for the session; [discover devices in the TUI](/rusty-bacnet/tui/discovery/) walks through it. The interactive shell of earlier releases is gone.

A discovery run in another process is not a documented persistent cache for a later one-shot process. A one-shot command takes an explicit target address instead.

## Find an object by name

For a one-shot command, use the parser-backed option:

```sh
bacnet find --name "Zone Temp" --wait 3
```

The one-shot command takes the name through `--name` or as a plain word, `bacnet find "Zone Temp"`; giving both is a usage error. The terminal UI's `:find` is a separate surface and must not be assumed identical to the one-shot command line.

## When discovery is empty

Test a known direct property read, confirm the local/remote UDP ports, and check firewall and interface routing. Consider VPN, container, and subnet boundaries before repeating increasingly broad scans. Keep sanitized diagnostics with the actual command and transport when opening an issue.
