[Build and integrate](/rusty-bacnet/integrate/overview/) / Restrict changes

A `BACnetServer` answers every peer that reaches it. Unless you configure it otherwise, any peer on any data link may write properties, create and delete objects, and subscribe. BACnet/SC mutual TLS doesn't change that: it authenticates a connection, not a service. This page shows where to decide who may change your device, which identity each decision can rely on, and what Python exposes.

The page describes **v{release}**. Two additions merged on `dev` after the release have [their own section](#on-dev-after-the-release), with an example program: DeviceCommunicationControl decisions, and rules on certificate names.

## One policy makes the server's decisions

Install one `ServerPolicy` with `policy(..)` on a server builder, or in `ServerConfig::policy`. Each method answers one question and has a default, so a policy overrides only what it decides. A *covered mutation* is any request in the table's first two rows: one that changes the object database or adds a subscription.

| Request | Method | Without a policy | When the policy denies |
|---|---|---|---|
| WriteProperty, WritePropertyMultiple, CreateObject, DeleteObject, AddListElement, RemoveListElement, AtomicWriteFile and the three SubscribeCOV services | `authorize_mutation` | Allowed | SERVICES / SERVICE_REQUEST_DENIED; nothing changes and no Audit record is written |
| WriteGroup, once per Channel it would write | `authorize_mutation` | Allowed | That Channel is skipped silently (the service is unconfirmed) |
| LifeSafetyOperation | `authorize_life_safety_operation` | Denied | SERVICES / SERVICE_REQUEST_DENIED |
| ConfirmedAuditNotification into the configured Audit Log sink | `authorize_audit_notification` | Denied | SERVICES / SERVICE_REQUEST_DENIED; nothing is stored |
| UnconfirmedAuditNotification | `authorize_unconfirmed_audit_notification` | Denied | Dropped silently |

Returning `false` denies, and so does a panic: the server catches it and treats it as a denial. Keep each method fast, nonblocking and free of side effects. The server calls them on its dispatch tasks, sometimes with the object database locked, so a method must not call back into the server. WritePropertyMultiple asks once per element, and elements before a denied one stay written. Each method's rustdoc says exactly when it is asked.

Some decisions are settings rather than policy methods:

- `MutationPolicy::DenyAll` refuses every covered mutation without asking the policy.
- DeviceCommunicationControl has a password, a static `DccPolicy` that denies every request by default, a restriction to listed source addresses and a disable rate limit. In v{release} the policy doesn't decide it.
- ReinitializeDevice runs only when you install an `on_reinitialize` handler, optionally behind a password. The policy doesn't cover it; the handler's `ReinitializeContext` has the same `principal()` for its own checks.
- TimeSynchronization is limited by `TimeSyncPolicy`.
- Routing control belongs to the router's `ControlAuthorizer`, not to the server.
- A [shared endpoint](/rusty-bacnet/integrate/shared-endpoints/)'s responder has its own mandatory Device-write authorizer.

### Compose decisions with FnPolicy

`FnPolicy` builds a policy from closures, one per decision: `FnPolicy::new().mutation(..).life_safety_operation(..)`. A decision without a closure keeps the default in the table. Without a mutation closure, the policy doesn't decide mutations at all, and they are allowed as if no policy were installed. Calling `policy(..)` again replaces the earlier policy, so put every decision in one chain. A policy in an `Arc` or a `Box` is still a policy, so one policy can be shared.

## Know who sent the request

Every policy context carries the source addresses the request claims, its `TransportProvenance` (how it arrived: unverified, over a hub, or over a verified direct BACnet/SC connection), and two principals derived from them:

- `principal()` is the fingerprint (`ScPrincipal`) of the verified leaf certificate, when the request came over a verified direct BACnet/SC connection from the device that originated it, and `None` otherwise.
- `forwarding_peer_principal()` is the fingerprint of the direct BACnet/SC peer that handed the request over, a router included.

Two kinds of request have no `principal()`:

- **Hub-relayed requests.** The hub authenticated its own TLS client. The originating node's certificate never reaches your device, so a policy can't tell one hub member from another.
- **Routed requests**, even over a direct connection. A request with a routed source (SNET/SADR: the network number and address of a device on another network) came from a device behind a router, and the connection authenticates only the router. `forwarding_peer_principal()` returns the router's principal, for a policy that trusts that router with everything it forwards.

B/IP, B/IPv6, MS/TP and Ethernet requests carry no principal at all. A source MAC, VMAC, device UUID or SNET/SADR is a claim the peer makes, never an identity. A gateway that re-originates requests shows its own principal, so trust a principal as far as everything its holder may relay.

A principal fingerprints the exact leaf certificate, so renewing a certificate changes it. In v{release}, a rule on principals lists the fingerprints it trusts, and the list must change when a certificate is renewed.

## Limit what reaches the server on BACnet/SC

These settings act before a request reaches the policy:

- **Hub admission.** A hub can bind each verified leaf certificate to its device UUID and allowed VMACs, and its admission policy can refuse same-UUID replacements. Admission doesn't carry a principal through the hub. See <a href={`${repository}/blob/v${release}/docs/rust-api.md#hub-certificate-bindings`}>hub certificate bindings</a> and <a href={`${repository}/blob/v${release}/docs/rust-api.md#bacnetsc-hub`}>the BACnet/SC hub</a>, which also covers `ScHubBroadcastRatePolicy`.
- **Network-layer control messages.** Each SC node limits the network-layer messages one source may hand in (`ScControlRateLimit`); application requests are never charged. See <a href={`${repository}/blob/v${release}/docs/rust-api.md#who-may-change-routes-518`}>who may change routes</a> for the defaults and how sources are counted.

## What Python exposes

Python's `BACnetServer` takes static settings only:

- `mutation_policy="permissive"`, the default, or `"deny_all"`, which denies the covered mutations through the same gate as Rust's `MutationPolicy::DenyAll`.
- `dcc_policy`, `dcc_password` and `dcc_source_restriction` for DeviceCommunicationControl, and `time_sync_policy` for clock changes.

Python has no policy callback, and no access to the requesting peer's principal or certificate. It has no direct BACnet/SC listener either, so a principal would always be absent there. A Python callback that sees the request context (issue #1966) and certificate names for Python (issue #2022) are merged on `dev`; see [Python callbacks and certificate names](#python-callbacks-and-certificate-names).

## On `dev` after the release

These additions were merged on `dev` after v{release}. Until docs.rs builds a release with them, their rustdoc is in the <a href={`${repository}/blob/dev/crates/bacnet-server/src/policy.rs`}>dev source of bacnet_server::policy</a>.

### DeviceCommunicationControl decisions

`ServerPolicy::authorize_device_communication_control`, or `FnPolicy::device_communication_control`, decides DCC requests (#1964). The static checks run first: the password, the refusal of the deprecated DISABLE, `DccPolicy` and the source restriction. A request any of them refuses never reaches the policy, so under the default `DccPolicy::DenyAll` the policy is never asked. The policy is asked before the disable rate limit is charged, so a denied requester spends none of that shared budget. A denial is answered SERVICES / SERVICE_REQUEST_DENIED, changes neither the state nor a running timer, and is counted in `dcc_outcome_counters` as `policy_denied_total`, which also counts the static refusals by `DccPolicy::DenyAll`, the source restriction and the rate limit. Without a policy, the method's default allows.

### Rules that survive certificate renewal

With the `sc-tls` feature, every policy context also has `certificate()` and `forwarding_peer_certificate()`: the verified leaf certificates behind the two principals, under the same rules (#1965). Both are `None` for hub-relayed and non-SC requests, and `certificate()` is `None` for a routed one. `ScPeerCertificate::metadata()` gives the subject, the issuer and `subject_alt_names()`, the certificate's DNS, URI, email and IP names (`ScSubjectAltName`) in certificate order. A rule on a name keeps working when the certificate is renewed with the same name, with no fingerprint list to update.

Compare names for equality:

- A name is the certificate's exact text. DNS case is not folded, and a wildcard such as `*.example.com` is returned as written, never expanded.
- An IP name compares as an IP address, so an IPv4-mapped IPv6 name doesn't equal the IPv4 address.
- Don't match by suffix. A rule that accepts any name ending in `.example.com` accepts every certificate the CA issues under that domain.
- Allow on a name you find rather than deny on one you miss. A missing, repeated or malformed name extension gives no names, and `metadata()` is `None` when the certificate can't be parsed.
- Never log a certificate's contents. The `Debug` output of these types leaves them out.

A name is only as trustworthy as the CA that signed it: trust only the CAs that issue your operators' certificates.

### Example: writes and DCC from one certificate name

This program allows covered mutations and DCC only from a verified direct BACnet/SC peer whose certificate carries a DNS name equal to the one you configure. It builds a server configuration with that policy, a DCC password and `DccPolicy::RequirePassword`, then checks that a request without a certificate is denied. It doesn't open a socket.

Only a server with a direct BACnet/SC listener sees certificates. On a server that only joins a hub, every request is hub-relayed, and this policy denies every write and DCC request.

From the directory containing `Cargo.toml`, give the DCC password in the environment and the operator's DNS name as the only argument:

```sh

Those tests don't exercise the allow path. The server's own tests do, over real direct TLS: a renewed certificate with the same DNS name stays allowed.

### Policy calls off the lock

Every policy decision for a received request now runs on Tokio's blocking pool, with no database guard held (#2032), so a policy that blocks delays only its own request, and `stop()` doesn't wait for it. A call that never returns still keeps the process from exiting. WritePropertyMultiple asks about each element, in order up to the first denial, before it takes the write lock; a denial still leaves the elements before it written.

### Python callbacks and certificate names

- `BACnetServer(mutation_policy=...)` also takes a callable that gets a redacted `MutationContext` and decides each covered mutation; an exception or an answer that isn't a bool denies (#1966).
- `ScCertificateMetadata.subject_alt_names` gives a certificate's DNS, URI, email and IP names as written (#2022). A `MutationContext`'s certificate accessors are `None`, since Python has no direct BACnet/SC listener.
- `BACnetClient` and `BACnetServer` take `sc_control_rate_limit=(burst, per_second)` for the BACnet/SC control-message rate limit (#1969).
- `BipEndpoint`, `ScEndpoint` and `MstpEndpoint` take `device_write_policy`, a callable that decides writes to the local Device under the same fail-closed rules (#2033).

### Local access authorization

`BACnetServer::authorize_access_local` records the result of an access decision your application made for a credential presented at an Access Point. It is physical access control, separate from the network decisions above; see <a href={`${repository}/blob/dev/docs/local-access-authorization.md`}>completed local access authorization</a>.
