The stack is a set of crates, each built on the ones in the layers below it. Depend on the highest one that covers your task: `bacnet-client` to read and write remote devices, `bacnet-server` to serve objects, `bacnet-endpoint` for both roles on one transport, and the portable cores for firmware without an operating system. Every item, with its feature gates and examples, is in each crate's rustdoc on docs.rs; this page helps you find the crate.

Each link opens the crate's documentation for v{release}. All crates but `bacnet-time` share that version; `bacnet-time` versions on its own, so its link opens the latest build, and docs.rs's version menu picks another. A crate's rustdoc lists the features its docs.rs build turns on.

:::note[On `dev` after the release]
This page is generated from the `dev` branch and tracks the next release. A crate merged after v{release} is marked unreleased and links to its source instead of docs.rs, and features or dependencies added since may not be in the released crates. The <a href={`${repository}/releases/tag/v${release}`}>v{release} release notes</a> and the <a href={`${repository}/tree/dev/changelog.d`}>changes waiting for the next release</a> say what changed.
:::

Lifecycle, ownership and migration contracts that span crates are in the <a href={`${repository}/blob/v${release}/docs/rust-api.md`}>Rust API guide</a> and the <a href={`${repository}/blob/v${release}/docs/architecture.md`}>architecture notes</a>. For a first program, start with [Embed with Rust](/rusty-bacnet/start/rust/) or [Run on a microcontroller](/rusty-bacnet/start/embedded/).
